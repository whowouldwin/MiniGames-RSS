# MiniGames — Story 1

Responsive single-page application for the RS School Qualifying Stage. Built with TypeScript, Vite and Sass, without JavaScript or CSS UI frameworks.

- [Live application](https://whowouldwin.github.io/minigames/)
- [Assignment](https://github.com/rolling-scopes-school/qualifying-stage/blob/main/tasks/minigames/story-1.md)
- [Figma design](https://www.figma.com/design/QbBovAU9KY8y2ll2onhnlv/MiniGames--Copy-?node-id=0-1)
- [Verification and acceptance checklist](docs/verification.md)

## Run locally

Use Node.js 24 (minimum 22.12) and npm.

```sh
npm ci
npm run dev
```

```sh
npm run check         # TypeScript, ESLint, Prettier, production build
npm run typecheck
npm run lint
npm run format:check
npm run format        # Apply formatting
npm run build
npm run preview
```

## Implemented scope

Home includes the header, animated mobile navigation, hero, static carousel, leaderboard, developer section and footer. Login and registration share an animated native dialog with semantic fields, keyboard navigation, inline switching, Escape/backdrop dismissal and password visibility.

Story 1 intentionally has no backend requests, authentication, validation errors or functional carousel controls. Hero/developer buttons are presentation-only. Navigation and social links return to Home; the footer also links to RS School and the developer's GitHub profile.

The current written requirement takes precedence over older artwork: cards narrower than 288px show only the image. Wider cards show their title, likes and rating.

## Structure

- `src/app`: application composition and the main landmark.
- `src/components`: co-located UI components, controllers and Sass.
- `src/styles`: shared tokens, mixins, typography and global styles.
- `src/assets`: locally stored fonts, images and exported Figma icons.
- `docs`: review checklist and screenshots.

All page content is generated by TypeScript. Static HTML contains metadata and the entry script only.

## Git workflow and deployment

Task branches target `story-1` through separate pull requests. The final `story-1` → `main` pull request remains **unmerged** for cross-check review.

Husky validates commit messages and aborts pushes on ESLint/Prettier errors. GitHub Actions repeats type, lint, formatting and build checks. Pushes to `story-1` publish GitHub Pages with the `/minigames/` base path.
